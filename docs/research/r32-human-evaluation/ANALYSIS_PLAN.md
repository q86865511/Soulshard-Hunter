# 真人資料分析規則（先於資料）

## 資料分類
- observed_play：實際遊玩所見事件。
- self_report：受測者對剛才經驗的陳述。
- concept_interview：尚未實作功能的概念偏好。
三者分開呈現；意願不等於行為，概念偏好不等於手感或留存。

## 指標
- 自願退出時間：只有 end_reason=voluntary_quit 才是退出事件；timebox、外部打斷、技術故障另列，不記 0%／100% 的錯誤分母。
- 重試：清楚列出有結算後選擇機會的人數、真正開新局的人數及其時間。口頭意願用原量尺和引言呈現，不代換成重試率。
- 卡點：任務是否完成、耗時、是否需協助；同一參與者的多次事件不能當成多位使用者。
- co-op：以成對 session 記錄，另列主機與訪客觀點；技術中斷與 UX 理解問題分開。
- 短局／手動瞄準：目前只可報概念偏好；需要可玩原型與實測才可聲稱實際改善。

## 分析步驟
1. 檢查匿名 participant_id、session_id、來源類型、版本和時間欄位；保留缺漏，不猜填。
2. 合併同一人的重複紀錄，列總人數、session 數、背景分布與已覆蓋任務。
3. 用「觀察 → 原話 → 可能解釋 → 可驗證修改」表格整理；至少列一個替代解釋。
4. 問題優先序依阻擋程度、重現人數及情境判定；小樣本不推估全體玩家比例，也不以單句評論宣稱因果。
5. 研究者先寫觀察，再看 bot 診斷；bot 可提供背景，不能補上缺失的人類意願。
6. 原始資料零筆時輸出「待資料」，不生成虛構平均數、人物或發現。

## 覆蓋矩陣
| 問題 | 必要證據 | 目前狀態 |
|---|---|---|
| 自願退出／截尾 | 真實單人事件與原因 | 待資料 |
| 重試意願與行為 | 結算後選擇＋自述，分欄 | 待資料 |
| 短局需求 | 真人概念訪談；實玩效果另待原型 | 待資料 |
| 手動瞄準需求 | 現行操作觀察＋真人概念訪談；手感另待原型 | 待資料 |
| co-op UX | 至少兩位真人共同遊玩與兩種角色觀察 | 待資料 |
