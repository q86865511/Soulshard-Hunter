# R32 真人評估流程（待執行）

狀態：尚無真人資料。使用者於 2026-09-16 明確回覆「目前沒有真人受測資料」。本文件是研究工具，不能當成已完成評估。

## 研究問題
- 玩家何時自行停止？原因是時間、困難、理解、重複感或其他因素？
- 結算後是否真的再開一局？口頭意願與實際行動分開。
- 對短局與手動瞄準的需求是什麼？
- 兩位真人在加入、辨識自己、合作與中斷恢復時遇到哪些問題？

目前產品是約 20 分鐘局、武器自動瞄準。**短局與手動瞄準尚無可供比較的正式原型**；本輪可做概念訪談，但不得把它寫成這些模式的實玩效果。

## 受測安排與紀錄
建議首輪涵蓋不同熟悉度的 3–5 位玩家，至少一組兩位真人的 co-op；依實際可取得的人員確認排程，不虛構人數。小樣本只支持問題發現，不估母體比例。
使用匿名代碼，不收真名、密碼、聯絡方式。受測者可隨時停止；錄影需事先同意，沒有錄影也可用手記。原始紀錄放 .pipeline/human-study/（不入版控），只提交去識別的分析摘要。

主持人先記錄實際 URL／版本／可查證 build commit、瀏覽器、輸入裝置、既有進度；不能只抄目前 git HEAD。單人可使用自選的乾淨瀏覽器設定檔；不要重設或覆寫受測者存檔。Co-op 使用受測者自己的合法測試帳號，帳號／測試環境尚未備妥時不代替他人註冊。

## A. 開場（約 3 分鐘）
逐字說明：「我們在測遊戲，不是在考你。你可以繼續玩、停止或跳過任何問題。請說出你當下看見什麼、想做什麼；沒有正確答案。」
記錄同類遊戲熟悉度（0–4）及今日可用時間。避免先介紹研究假說、bot 結果或告訴玩家應該重試。

## B. 單人自由遊玩
1. 請玩家自行從首頁開始一局，記錄找到入口、看懂目標與控制所需時間。
2. 讓玩家決定何時停止；研究時段上限建議 25 分鐘。若主持人結束時段，標記 timebox／右截尾，**不是自願退出**。
3. 記錄關鍵事件：第一次受傷、第一次升級、第一次不理解、停頓、死亡／通關／自行退出，以及當時原話。
4. 結算後保留中立選擇機會：「接下來你可以自由選擇繼續或停止。」只有真的開始下一局才記 retry_observed=true；詢問的 retry_intent 另欄記錄。
5. 問「剛才在哪一刻最想停下？發生什麼事？」不要替玩家選原因。

## C. 概念訪談（不混入實玩指標）
短局：先問理想可用時段，再以順序交替方式呈現「現行完整 20 分鐘局」與「較短、另行平衡的一局」概念。問使用情境、擔心失去什麼；不承諾未設計的獎勵／難度。
手動瞄準：先問目前是否理解攻擊目標，再討論「保留自動瞄準」與「可選手動控制方向」概念，記錄偏好與理由。沒有可玩原型時，不能評估其手感、認知負荷或留存效果。
每筆相關資料的 evidence_type 必須是 concept_interview；不能標為 observed_play。

## D. 兩位真人 co-op
1. 玩家自行完成建立／加入房間、選角、準備與開局；觀察者只在完全卡住時協助，並記 assistance。
2. 遊玩至少能遭遇敵人與一次升級；分別問兩位玩家如何辨識自己、隊友與共同目標。
3. 先告知後，讓其中一位關閉自己的遊戲頁面；觀察另一位收到的提示、是否能安全回到可操作狀態。不要中斷他人的整台裝置網路。
4. 換主機／訪客角色再走一次加入流程。中斷結果依現有產品行為記錄，不預設一定能無縫續局。
5. 兩位玩家分開回答最困惑、最順暢、最想改的地方，避免相互代答。

## 完成條件
必須有真正的原始紀錄、資料來源與 coverage matrix，才能產出 H2 結論。若沒有真人、只有單人、或只有概念意見，相應項目維持未驗證。
本輪沒有招募、傳送訊息、實際試玩或蒐集個資；這些不因文件建立而視為已完成。
