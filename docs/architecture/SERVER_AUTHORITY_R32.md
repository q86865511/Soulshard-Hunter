# R32 伺服器權威合作模擬

狀態：本地正式實作與回歸驗證完成；尚未發布或部署。使用者已授權必要的 src、連線協定及打包設定調整；遊戲數值與存檔格式保持不變。

## 責任與資料流

每個合作房間由獨立 Node 子程序執行既有 runScene／World／Player／Enemy。src/bootstrap.js 共用完整內容啟動，headless.js 提供不繪圖的環境；保留遊戲更新、粒子呼叫與 RNG 消耗。伺服器固定以 1/120 秒更新，約 18Hz 傳送快照。瀏覽器中的房主、隊員都使用 coop 場景呈現與預測自己的位置。

- 原房主的完整升級選擇與 meta 加成、隊員的基礎屬性／武器選擇沿用原規則。
- 開局取用原房主**已存在的雲端存檔**，檢查天賦、設施、鍛造上限及資料型別；角色與起始武器必須相符。沒有新增開局前自動上傳。
- 原房主存檔仍是本局永久進度與結算的歸屬；大廳管理權移轉不會把角色屬性或獎勵歸屬換給其他人。
- 單機仍在瀏覽器執行，BALANCE、內容定義、存檔 key／版本／格式未改。
- 初始雲存檔繼承離線進度的信任限制，不能據此宣稱歷史進度已驗真。合法輸入形式的 bot 也不在此驗證範圍；共享世界快照尚未按玩家視野裁切。

## 協定與輸入邊界

WebSocket /rt 使用 protocol=2；resumeCid 來自同一分頁的 sessionStorage，重連仍須通過 JWT 身分與原連線歸屬檢查。舊客戶端收到更新提示，新客戶端遇到舊服務端會拒絕開局。

| 訊息 | 權威來源與檢查 |
|---|---|
| input | 伺服器綁定 cid；runId、protocol、遞增 seq、有限且有界向量；方向正規化，dash／互動合併為單次輸入 |
| levelpick | 僅能挑自己當前 choiceId 的有效索引，套用伺服器持有的選項 |
| runstart／snap／runend／levelup／settlement | 只由可信子程序產生；所有玩家送來的世界或結果封包均忽略 |
| 重連 | 同一角色換綁新 cid，輸入序號重設；角色不重複建立 |
| 觀戰 | 可收快照，沒有可送入模擬的 actor |

輸入閘門每個角色最多持續 60 次／秒、瞬間 12 次；WebSocket 入站上限 16KiB，出站積壓超過 2MB 會關閉慢連線。子程序快照只保留最新待送幀；重要訊息有界排隊。封包中沒有可控制伺服器 dt、傷害、XP 或勝負的欄位。

## 斷線、離房與故障

斷線保留 20 秒重連機會（既有清理週期另有排程延遲）。角色停止接收輸入，仍在世界中承受傷害；世界時鐘繼續，重連沿用當前血量與死亡狀態。已結束的對局不會因重連復活。

原房主離房後，其他隊員仍使用同一世界；若僅剩暫時離線的隊友，保留其重連窗口。最後一位玩家離房會先觸發可信結算，再回收子程序。放棄對局沿用原有放棄計分／聲望公式。

每個子程序 heap 上限 256MB；同時模擬房數由 AUTHORITY_MAX_ROOMS 控制，預設 2、可設 1–16。啟動逾時、超過 2 秒更新積壓、10 秒沒有子程序訊息或程序故障會中止該房間。沒有新增固定遊戲時長上限。伺服器重啟不恢復記憶體中的戰場。

## 結算與存檔衝突

新增 authority_results 以 runId 記錄原房主、結果及完整結算 meta；runs.authority_run_id 表示可信模擬來源。單一 SQL 原子地建立收據、寫入排行榜，並在雲存檔仍等於開局版本時更新存檔。重播同一 runId 不會重複入帳。

若雲存檔已改變，保留收據與結果，不覆蓋較新進度；不自動合併有衝突的存檔。GET /api/authority/results 只回傳目前帳號最近十筆結果與保存狀態。勝負先以 runend 送達，settlement 另行確認保存結果；等待超過 30 秒會回報尚未確認並釋放資源。資料庫錯誤或逾時不會把勝負改成斷線，也不會假稱已入帳。合作中的帳號不能由另一個客戶端 PUT 覆蓋存檔。

原房主在結算畫面讀取雲端結果時，會再核對帳號、目前對局與本機進度；延遲回應不能蓋掉新進度或切換後的帳號。

REST /api/runs 與 /api/runs/guest 保留原單機合理性檢查，但不接受客戶端宣稱的合作成績。排行榜新增 authority 標記；單機／舊紀錄不能冒充伺服器模擬。

## 本地驗證與限制

- 完整 registry：27 角色、43 武器、54 被動、63 敵人、28 道具、60 裝備、20 天賦、11 設施。
- 270 個角色／地圖組合，各執行一秒雙人世界，共 32400 ticks；不把這個啟動測試稱為長局平衡測試。
- Chromium／Node 固定測試輸入：10 個時間點，完整比較快照、傷害、XP、選項、武器與終局。兩邊靜音，因音效噪音會消耗共用 RNG；敵人索引透過各自 runstart.defs 還原後比較。
- 兩個隔離瀏覽器帳號走真實 HTTP／WebSocket 與原生子程序，檢查房主輸入、重新整理後重連、房主離房、最後離房結算、Esc 選單；DB 為本機假資料。
- PGlite 執行實際 PostgreSQL schema／SQL，檢查重播、換槽、存檔衝突、整筆回滾及 API 身分隔離。它不是多程序 PostgreSQL 壓力測試。
- Node 22.23.2：兩間三人房開局 12 秒，兩房各 1405 個取樣；p95 0.386／0.376ms，p99 0.592／0.609ms，RSS 約 87.8／87.9MB。這是 Windows x64 開局資料，不能外推晚期怪潮或 Oracle ARM 容量。
- Docker Linux x86_64 的無網路測試容器已驗證打包配置、正式依賴、API、房間、快照及結算；沒有部署。ARM 容量仍需在目標環境另行驗證。

## S1 歷史探針

升級前是 browser-host relay：伺服器只轉送世界。Node 24 直接匯入 World 在 document 初始化失敗；最初 shim 探針僅載入 12／0／0／1 個角色／武器／被動／敵人。R32 改為共用 bootstrap 與完整場景載入後才達到上述完整 registry。保留 tools/authority-probes/ 作為舊信任邊界及匯入限制的紀錄，不把探針結果當成正式驗收。
