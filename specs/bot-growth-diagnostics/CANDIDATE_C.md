# 候選 C：XP 走位吸引權重（預先登記）
日期：2026-09-16。此規則於 A/B 診斷完成後、A/C 實作與實驗前固定。

## 診斷依據
- A/B 診斷各 270 局，無最終 error，XP 價值守恆違例 0。
- 90–120 秒：A/B kills/分為 110.00／61.80，XP 掉落/分為 429.68／237.54。B 新武器選擇僅 46 次，A 為 680 次；武器升級供給面板比例為 10.83%／29.33%。成長落差較符合新武器與火力、XP 供給的回饋不足，不能只歸因於拾取。
- A 全局 XP 過期比例 23.85%，但此數受少數長局影響。每局前 min(120 秒,存活時間) 合計：掉落 91,192，收集 53,924（59.13%），過期 14,072（15.43%），剩餘 23,196。A 的逐局過期比例中位為 17.84%。
- A 多個不同武器等級可升級的面板僅 31/1681，其中實際選升級 30 次；單改升級排序目前可觀測的觸發範圍較小。
- 以上支持測試 A 的 XP 收集機會，不證明加權一定改善通關，也不聲稱找到了最佳權重。

## 唯一變因
C 保留 A 的全部選擇策略。只把合格 XP 拾取物的走位吸引權重 **1 → 1.5**。
原 PICKUP_GAIN=0.6，因此 C 的 XP 吸引係數為 0.9；非 XP 仍為 0.6。1.5 是一次固定的溫和候選值，未以先導／確認結果調參。

保持：敵人／boss 斥力、安全距離閘、與最近敵人同方向排除、牆面與體寬檢查、dash、anti-idle、dt、選項優先序、seed tie-break。只允許 XP 分量造成方向差異，不改 src/ 或遊戲數值。

## 可稽核性
- policy C = choiceStrategy A，xpWeight 1.5；A = choiceStrategy A，xpWeight 1。
- 每局記錄 policy、實際係數與每秒 A/C 同輸入影子比較的分歧數；影子策略不驅動世界、不取遊戲 RNG。
- A/C 都啟用 growth-v1，方法與抽樣相同。manifest 鎖定來源、策略、診斷與參數。
- A 預設輸出與原版 10,000 個輸入比對須一致；真 Chromium 必須證明 C 的控制輸入確實使用 1.5。

## 實驗
A/C 先導各 270（共 540），seed=1；只判斷資料、分派與可執行性，不選擇最佳參數。
A/C 確認各 4050（10 生態×27 角色×5 局×3 seed），共 8100，與診斷／先導分目錄。
依生態交替 AC/CA、parallel=4；固定程式 commit 後執行，原始失敗保留。遊戲 RNG 不受控，不能視為同世界配對。

## 主要判準（不因診斷或先導結果改動）
四項需全部通過：
1. C−A 有效通關率至少 +1 個百分點。
2. 生態×角色分層、兩組獨立 bootstrap 5000 次（分析 seed 20260915），95% CI 下界 >0。
3. clear/全部局方向一致。
4. C 的 timeout/error 排除率不得高於 A。
否則保留 A。所有單格與副作用都照實報告，不挑勝出格子。

次要機制指標：共同早期窗口 XP 收集/分、XP 過期比例、升級節奏、存活分位數、各生態結果；它們解釋機制，不取代主要採用門檻。可能風險是 XP 吸引提高後更常靠近危險，需由實驗檢驗。
